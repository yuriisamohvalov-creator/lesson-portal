# Импорт статей из каталога видео (админка)

## Зачем

Ручной импорт курсов по луку (август 2026) повторял один сценарий для каждого MP4:

1. создать статью в категории;
2. залить видео в MinIO, дождаться `ready` и постера;
3. опубликовать статью;
4. добавить урок в курс с порядком.

Этот документ описывает **кнопочный запуск** того же сценария из админки с **выбором каталога на сервере**, без привязки к одному набору файлов.

## UI

- Страница: `/admin/video-import` (пункт «Импорт видео» в `AdminNav`).
- Обход каталога: корни из `VIDEO_CATALOG_IMPORT_ROOTS`, кнопки «вверх» / быстрый переход к корню, клик по подкаталогу.
- Предпросмотр: список MP4/WebM (с учётом «в подкаталогах»).
- Параметры:
  - категория статей;
  - опубликовать статьи сразу (по умолчанию да);
  - курс: **новый** (название, slug, описание), **существующий** или **без курса**.
- Запуск создаёт **фоновую задачу**; прогресс опрашивается по `jobId`.

## API (только `ADMIN`)

| Метод | Путь | Назначение |
|--------|------|------------|
| GET | `/api/admin/video-catalog-import/roots` | сконфигурированные корни |
| GET | `/api/admin/video-catalog-import/browse?path=` | содержимое каталога |
| POST | `/api/admin/video-catalog-import/preview` | список файлов для импорта |
| POST | `/api/admin/video-catalog-import/run` | старт задачи |
| GET | `/api/admin/video-catalog-import/jobs/:jobId` | статус и результаты |

## Backend

Модуль: `backend/src/video-catalog-import/`.

- Пути проверяются через `resolve()` и whitelist корней (path traversal запрещён).
- Заголовок статьи — из имени файла (без расширения, `_` → пробел).
- Slug — транслитерация латиницей + суффикс при коллизии (как у обычных статей).
- Повторный импорт: если для **того же относительного пути** в каталоге уже есть статья (маркер `catalog-import:…` в тексте или legacy-блок «Видеоурок из каталога» с тем же `<code>путь</code>`), файл **не дублируется** — строка помечается `skipped`, при готовом видео исходник с диска удаляется; при выборе курса статья по возможности добавляется в курс. Совпадение только по title/slug **не используется** (у кириллических имён slug часто схлопывается в короткие латинские слова вроде `blender`).
- Видео: `PutObject` из локального файла, `processStatus: ready`, постер через `VideoThumbnailService`.
- После успешной заливки в MinIO и генерации постера исходный MP4/WebM **удаляется** с диска каталога; путь снова проверяется по whitelist корней. Ошибки публикации или добавления в курс файл уже не откатывают.
- Публикация: `PUBLISHED` + запись в `moderation_logs` (`APPROVED`, комментарий об auto-import).
- Задачи хранятся **в памати процесса** (после рестарта backend теряются; для длинных каталогов перезапускать backend во время импорта не стоит).

## Конфигурация

`.env` / prod secrets:

```bash
# Несколько корней через двоеточие (Linux)
VIDEO_CATALOG_IMPORT_ROOTS=/data/lessons-import:/mnt/plex/lessons
```

На **brix-pc** каталог с исходниками монтируется в backend через `docker-compose.prod.yml`
(переменные `VIDEO_CATALOG_IMPORT_HOST_PATH`, `VIDEO_CATALOG_IMPORT_CONTAINER_PATH`,
`VIDEO_CATALOG_IMPORT_ROOTS`). При деплое Ansible role `deploy_brix_pc` прописывает их в
`.env.runtime` из `inventory/group_vars/brix_pc/main.yml` (по умолчанию
хост `/app/6tb/lessons-portal/import` → контейнер `/app/6tb/lessons-portal/import:ro`,
`VIDEO_CATALOG_IMPORT_ROOTS=/app/6tb/lessons-portal/import`).

## Отличия от импорта «лук»

| Было (ручной/agents) | Стало |
|----------------------|--------|
| Жёсткий путь и manifest курсов | Любой каталог под whitelist |
| Фиксированные title/порядок из плана | Title из имени файла, порядок — сортировка путей |
| SHA-256 сверка и удаление исходников | После заливки в MinIO и постера исходный MP4/WebM удаляется; при ошибке до загрузки файл остаётся |
| Отдельные прогоны по 4 курсам | Один UI: новый или существующий курс |

## Дальнейшие улучшения (не в MVP)

- Персистентные jobs (Redis/БД) и resume после рестарта.
- Опциональная сверка SHA-256 перед удалением исходника.
- Manifest JSON в каталоге (переопределение title/order/slug).
- Rate limit / очередь с одним активным импортом на инстанс.

