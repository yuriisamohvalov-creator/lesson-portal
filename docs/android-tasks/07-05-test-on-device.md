# Этап 7.5: Проверка на реальном устройстве

## Цель этапа

Провести тестирование приложения на физическом Android-устройстве для выявления проблем, которые не проявляются на эмуляторах.

## Почему важно тестировать на реальном устройстве

| Аспект | Эмулятор | Реальное устройство |
|--------|----------|---------------------|
| Производительность | Идеальная (зависит от хоста) | Реальная (ограничения железа) |
| Память | Виртуальная | Физическая, ограничена |
| Сеть | Стабильная | Реальные условия (3G/4G/WiFi) |
| Камера | Эмулированная | Реальная аппаратная |
| Датчики | Программные | Физические (акселерометр, GPS) |
| Батарея | Не влияет | Реальное потребление |
| Нагрев | Отсутствует | Может влиять на производительность |
| Звук | Через хост | Через динамики устройства |

## Подготовка устройства

### Шаг 1: Включение режима разработчика

**Инструкция:**

1. Открыть **Настройки** на устройстве
2. Прокрутить вниз до **О телефоне** (или **Об устройстве**)
3. Найти **Номер сборки** (Build Number)
4. Быстро нажать на **Номер сборки** 7 раз
5. Ввести пароль/PIN устройства (если требуется)
6. Появится сообщение: "Вы стали разработчиком!"

**Расположение "Номера сборки" на разных устройствах:**

| Производитель | Путь |
|---------------|------|
| Samsung | Настройки → О телефоне → Сведения о ПО → Номер сборки |
| Xiaomi | Настройки → О телефоне → Версия MIUI |
| Huawei | Настройки → О телефоне → Номер сборки |
| OnePlus | Настройки → О телефоне → Версия прошивки |
| Google Pixel | Настройки → О телефоне → Номер сборки |

### Шаг 2: Включение USB-отладки

1. Открыть **Настройки**
2. Перейти в **Для разработчиков** (появилось после шага 1)
3. Найти и включить **Отладка по USB** (USB Debugging)
4. Подтвердить предупреждение
5. Дополнительно включить:
   - **Отладка по Wi-Fi** (опционально, для беспроводного подключения)
   - **Не выключать экран** (для удобства тестирования)

### Шаг 3: Подключение к компьютеру

**Через USB:**

1. Подключить устройство к компьютеру через USB-кабель
2. На устройстве появится запрос на разрешение отладки
3. Нажать **Разрешить** (Allow)
4. Опционально отметить **Всегда разрешать с этого компьютера**

**Проверка подключения:**

```bash
adb devices
```

**Ожидаемый вывод:**
```
List of devices attached
ABC123XYZ    device
```

**Если устройство не отображается:**

**Linux:**
```bash
# Добавить udev правило
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="<vendor_id>", MODE="0666", GROUP="plugdev"' | sudo tee /etc/udev/rules.d/51-android.rules

# Перезапустить udev
sudo udevadm control --reload-rules
sudo service udev restart

# Vendor IDs популярных производителей:
# Samsung: 04e8
# Google: 18d1
# Huawei: 12d1
# Xiaomi: 2717
# OnePlus: 2a70
```

**Windows:**
1. Установить драйверы устройства (обычно через Windows Update)
2. Для Samsung: установить Samsung USB Drivers
3. Для Xiaomi: установить Mi USB Drivers

**macOS:**
- Обычно работает без дополнительных драйверов
- Для некоторых устройств может потребоваться Android File Transfer

### Шаг 4: Беспроводное подключение (опционально)

**Первичная настройка через USB:**

```bash
# Включить ADB over WiFi
adb tcpip 5555

# Отключить USB
adb usb

# Узнать IP-адрес устройства
adb shell ip addr show wlan0 | grep "inet "

# Подключиться по WiFi
adb connect <IP-адрес>:5555

# Проверить подключение
adb devices
```

**Преимущества беспроводного подключения:**
- Свобода перемещения с устройством
- Возможность тестирования в разных локациях
- Нет помех от кабеля

**Недостатки:**
- Медленнее передача файлов
- Может обрываться соединение
- Требует стабильной WiFi сети

## Установка приложения

### Способ 1: Через Gradle

```bash
cd android

# Сборка и установка debug версии
./gradlew installDebug
```

### Способ 2: Через ADB

```bash
# Сборка APK
./gradlew assembleDebug

# Установка на устройство
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

**Флаги установки:**
- `-r`: Заменить существующее приложение
- `-t`: Разрешить установку test-only пакетов
- `-d`: Разрешить установку downgrade (более старой версии)

### Способ 3: Прямая установка APK

1. Скопировать APK на устройство:
   ```bash
   adb push app/build/outputs/apk/debug/app-debug.apk /sdcard/Download/
   ```

2. На устройстве открыть **Файлы** → **Download**
3. Нажать на APK файл
4. Разрешить установку из неизвестных источников (если требуется)
5. Нажать **Установить**

## Ручное тестирование на устройстве

### Чек-лист базового функционала

Использовать чек-лист из **Этапа 7.4 (Smoke-тесты)** с фокусом на:

#### ✅ Производительность

- [ ] Время холодного старта < 3 секунд
- [ ] Время горячего старта < 1 секунды
- [ ] Скролл списков плавный (без рывков)
- [ ] Переключение между экранами мгновенное
- [ ] Анимации работают плавно (60 FPS)

**Измерение времени запуска:**
```bash
# Запустить приложение и измерить время
adb shell am start -W ru.samoh.lessonsportal/.ui.MainActivity

# Ожидаемый вывод:
# Starting: Intent { act=android.intent.action.MAIN cat=[android.intent.category.LAUNCHER] cmp=ru.samoh.lessonsportal/.ui.MainActivity }
# Status: ok
# Activity: ru.samoh.lessonsportal.ui.MainActivity
# ThisTime: 1234
# TotalTime: 1456
# WaitTime: 1567
```

#### ✅ Потребление памяти

- [ ] Приложение не занимает более 200 MB в фоне
- [ ] Нет утечек памяти при длительном использовании
- [ ] Приложение не закрывается системой при нехватке памяти

**Проверка памяти:**
```bash
# Получить информацию о памяти приложения
adb shell dumpsys meminfo ru.samoh.lessonsportal

# Пример вывода:
# Applications Memory Usage (kB):
# Uptime: 12345678 Realtime: 12345678
#
# ** MEMINFO in pid 12345 [ru.samoh.lessonsportal] **
#                    Pss  Private  Private  SwapPss     Heap     Heap     Heap
#                  Total    Dirty    Clean    Dirty     Size    Alloc     Free
#   Native Heap      123     1000        0        0     8192     4500     3692
#   Dalvik Heap       45       30        0        0     2048     1200      848
#   ...
#   TOTAL            5000     4000      100        5    15000     8000     7000
```

#### ✅ Работа с камерой (если используется для аватара)

- [ ] Камера открывается при нажатии кнопки загрузки аватара
- [ ] Предпросмотр камеры работает
- [ ] Фото делается корректно
- [ ] Изображение загружается как аватар
- [ ] Разрешения запрошены корректно

**Проверка разрешений:**
```bash
# Проверить выданные разрешения
adb shell dumpsys package ru.samoh.lessonsportal | grep permission

# Выдать разрешение на камеру (если нужно)
adb shell pm grant ru.samoh.lessonsportal android.permission.CAMERA

# Выдать разрешение на хранение
adb shell pm grant ru.samoh.lessonsportal android.permission.READ_EXTERNAL_STORAGE
```

#### ✅ Работа со звуком

- [ ] Звуковые уведомления работают (если есть)
- [ ] Видео в статьях воспроизводятся со звуком
- [ ] Громкость регулируется системными кнопками
- [ ] Звук не прерывается при сворачивании приложения

#### ✅ Работа в фоновом режиме

- [ ] Приложение корректно сворачивается
- [ ] При возврате приложение восстанавливается (не перезапускается)
- [ ] Долгосрочные операции продолжаются (если есть)
- [ ] Уведомления приходят корректно

**Тестирование фона:**
1. Открыть приложение
2. Нажать кнопку Home
3. Подождать 30 секунд
4. Открыть приложение из Recent Apps
5. ✅ Приложение должно восстановиться, а не перезапуститься

#### ✅ Потребление батареи

- [ ] Приложение не разряжает батарею чрезмерно
- [ ] Нет фоновой активности без причины
- [ ] Wake locks освобождаются корректно

**Проверка потребления:**
```bash
# Получить статистику батареи
adb shell dumpsys batterystats --package ru.samoh.lessonsportal

# Или использовать Battery Historian (визуальный инструмент)
# https://github.com/google/battery-historian
```

## Инструменты профилирования

### Android Profiler (через Android Studio)

1. Подключить устройство
2. Запустить приложение
3. Открыть **View** → **Tool Windows** → **Profiler**
4. Выбрать подключенное устройство и процесс приложения

**Мониторинг в реальном времени:**
- **CPU**: Загрузка процессора
- **Memory**: Потребление памяти
- **Network**: Сетевая активность
- **Energy**: Потребление энергии

### Logcat на устройстве

```bash
# Просмотр логов в реальном времени
adb logcat | grep -i "lessonsportal"

# Сохранение логов в файл
adb logcat -v time > device-logs.txt

# Фильтрация по уровню важности
adb logcat *:E  # Только ошибки
adb logcat *:W  # Ошибки и предупреждения

# Очистка логов
adb logcat -c
```

### Проверка на утечки памяти с LeakCanary

LeakCanary уже подключён в debug-сборке.

**Как использовать:**

1. Установить приложение на устройство
2. Интенсивно использовать приложение:
   - Открывать/закрывать экраны
   - Загружать большие списки
   - Переключать ориентацию экрана
3. Следить за уведомлениями от LeakCanary
4. При обнаружении утечки:
   - Открыть уведомление
   - Изучить stack trace
   - Исправить код
   - Перепроверить

### Network Inspector

**Для проверки сетевых запросов:**

1. Установить Proxy-приложение (например, Charles Proxy или mitmproxy)
2. Настроить прокси на устройстве
3. Установить SSL сертификат
4. Наблюдать за запросами в реальном времени

**Или использовать Stetho/Chucker:**
```kotlin
// В debug сборке добавить Chucker
debugImplementation("com.github.chuckerteam.chucker:library:4.0.0")
releaseImplementation("com.github.chuckerteam.chucker:library-no-op:4.0.0")
```

## Тестирование в реальных условиях

### Плохое сетевое соединение

**Сценарии:**

1. **3G/EDGE:**
   - Отключить WiFi
   - Использовать мобильную сеть
   - Проверить загрузку контента

2. **Нестабильное соединение:**
   - Перемещаться между зонами покрытия
   - Проверить восстановление после обрыва
   - Убедиться, что данные не теряются

3. **Полный офлайн:**
   - Включить авиарежим
   - Проверить отображение кэшированных данных
   - Убедиться, что offline-banner появляется

### Различные условия освещения

- [ ] Экран читаем при ярком солнечном свете
- [ ] Тёмная тема комфортна в темноте
- [ ] Контрастность достаточная для всех элементов

### Разные ориентации устройства

- [ ] Портретная ориентация работает
- [ ] Ландшафтная ориентация работает
- [ ] Поворот не вызывает потерь данных
- [ ] UI адаптируется корректно

### Многозадачность

1. Открыть приложение
2. Переключиться на другое приложение
3. Вернуться обратно
4. ✅ Приложение должно восстановиться

**Тест с множеством приложений:**
1. Открыть приложение
2. Открыть браузер, соцсети, другие тяжёлые приложения
3. Вернуться к тестируемому приложению
4. ✅ Приложение не должно перезапускаться

## Возможные проблемы и решения

### Проблема: Устройство не определяется через ADB

**Решение:**
1. Проверить USB-кабель (попробовать другой)
2. Проверить USB-порт (попробовать другой)
3. Перезапустить ADB сервер:
   ```bash
   adb kill-server
   adb start-server
   ```
4. Переподключить устройство
5. Проверить драйверы (Windows)
6. Проверить udev правила (Linux)

### Проблема: Приложение крашится на устройстве, но работает на эмуляторе

**Возможные причины:**
- Нехватка памяти на устройстве
- Специфичное железо (процессор, GPU)
- Проблемы с разрешениями
- Отсутствие Google Play Services

**Решение:**
1. Изучить логи краша:
   ```bash
   adb logcat | grep -A 30 "FATAL"
   ```
2. Проверить доступную память:
   ```bash
   adb shell cat /proc/meminfo
   ```
3. Проверить разрешения:
   ```bash
   adb shell dumpsys package ru.samoh.lessonsportal
   ```
4. Протестировать на другом устройстве

### Проблема: Медленная работа на устройстве

**Решение:**
1. Закрыть лишние приложения на устройстве
2. Очистить кэш приложения:
   ```bash
   adb shell pm clear ru.samoh.lessonsportal
   ```
3. Проверить свободное место на устройстве
4. Оптимизировать тяжёлые операции в коде
5. Добавить pagination для больших списков
6. Использовать изображение меньшего размера

### Проблема: Перегрев устройства

**Решение:**
1. Снизить частоту обновлений UI
2. Оптимизировать фоновые задачи
3. Избегать длительных операций в главном потоке
4. Прекратить тестирование при сильном нагреве
5. Дать устройству остыть перед продолжением
