# Этап 7.8: Проверка Pre-Launch Report

## Цель этапа

Проанализировать автоматический отчёт Google Play Pre-Launch Report и устранить выявленные проблемы.

## Что такое Pre-Launch Report

**Pre-Launch Report** — это автоматический отчёт, который Google Play генерирует для каждого нового приложения или обновления. Отчёт содержит результаты автоматизированного тестирования вашего приложения на различных устройствах.

### Когда генерируется отчёт

- При загрузке первого релиза в любой трек тестирования
- При загрузке нового релиза после предыдущего
- После завершения обработки AAB файла

### Где найти отчёт

1. Открыть [Google Play Console](https://play.google.com/console)
2. Выбрать приложение **Lessons Portal**
3. В левом меню: **Качество** → **Pre-launch report** (Quality → Pre-launch report)
4. Выбрать последнюю сборку

---

## Разделы Pre-Launch Report

### 1. Сводка (Overview)

**Содержит:**
- Общее количество протестированных устройств
- Количество критических проблем
- Количество предупреждений
- Статус прохождения тестов

**Интерпретация:**

| Статус | Значение | Действия |
|--------|----------|----------|
| ✅ Отлично | 0 критических проблем | Можно выпускать |
| ⚠️ Предупреждение | Есть незначительные проблемы | Рекомендуется исправить |
| ❌ Критично | Есть серьёзные проблемы | Требуется исправление перед релизом |

---

### 2. Краши (Crashes)

#### Типы крашей

**Краш при запуске (Crash on launch):**
- Приложение закрывается сразу после запуска
- **Критичность:** Высокая
- **Действие:** Исправить обязательно

**Краш во время теста (Crash during test):**
- Приложение закрывается во время автоматического тестирования
- **Критичность:** Высокая
- **Действие:** Исправить обязательно

**ANR (Application Not Responding):**
- Приложение не отвечает более 5 секунд
- **Критичность:** Средняя/Высокая
- **Действие:** Оптимизировать производительность

#### Анализ краша

Для каждого краша отображается:

```
Устройство: Samsung Galaxy S21
Версия Android: 12
Сообщение об ошибке: java.lang.NullPointerException
Stack trace:
  at ru.samoh.lessonsportal.ui.MainActivity.onCreate(MainActivity.kt:45)
  at android.app.Activity.performCreate(Activity.java:8085)
  ...
```

**Действия:**
1. Изучить stack trace
2. Определить причину (NullPointerException, IndexOutOfBoundsException, etc.)
3. Воспроизвести локально (если возможно)
4. Исправить код
5. Протестировать на эмуляторе с аналогичной конфигурацией
6. Загрузить новый релиз

---

### 3. Проблемы совместимости (Compatibility Issues)

#### Типы проблем

**Проблемы с макетом (Layout issues):**
- Элементы UI выходят за границы экрана
- Текст обрезается
- Кнопки перекрываются

**Проблемы с ориентацией (Orientation issues):**
- Приложение не корректно работает в ландшафтной ориентации
- Данные теряются при повороте

**Проблемы с разрешениями (Permission issues):**
- Запрошены избыточные разрешения
- Разрешения не запрошены корректно

**Проблемы с API уровнями (API level issues):**
- Использование API, недоступных на старых версиях Android
- Отсутствие проверок версии

#### Пример отчёта

```
⚠️ Проблема совместимости
Устройства: Google Pixel 4a (Android 11), Samsung Galaxy A52 (Android 12)
Описание: Кнопка "Отправить" частично скрыта на экране создания статьи
Рекомендация: Использовать ConstraintLayout и проверить на разных размерах экрана
```

**Действия:**
1. Открыть скриншот проблемы
2. Определить паттерн (какие устройства затронуты)
3. Исправить layout в коде
4. Протестировать на эмуляторах разных размеров
5. Перезагрузить релиз

---

### 4. Производительность (Performance)

#### Метрики производительности

**Время запуска (Launch time):**

| Показатель | Норма | Требует внимания | Критично |
|------------|-------|------------------|----------|
| Холодный старт | < 2с | 2-5с | > 5с |
| Горячий старт | < 1с | 1-3с | > 3с |

**Потребление памяти (Memory usage):**

| Показатель | Норма | Требует внимания | Критично |
|------------|-------|------------------|----------|
| Пиковое потребление | < 200 MB | 200-400 MB | > 400 MB |

**Потребление батареи (Battery usage):**
- Оценивается относительно похожих приложений
- Может быть указано как "Выше среднего" или "Нормальное"

#### Рекомендации по оптимизации

**Если время запуска высокое:**
- Использовать App Startup library
- Отложить инициализацию библиотек
- Упростить главный экран
- Использовать Splash Screen API

**Если потребление памяти высокое:**
- Проверить утечки памяти (LeakCanary)
- Оптимизировать загрузку изображений (Glide/Picasso)
- Использовать pagination для списков
- Очищать кэши своевременно

### 5. Доступность (Accessibility)

#### Проверяемые аспекты

**Content descriptions:**
- У всех интерактивных элементов должны быть описания
- Для людей с нарушениями зрения (TalkBack)

**Размер элементов:**
- Минимальный размер кликабельной области: 48x48 dp
- Достаточный контраст между элементами

**Навигация:**
- Логический порядок фокуса
- Поддержка клавиатуры и D-pad

#### Пример рекомендации

```
⚠️ Проблема доступности
Элемент: Кнопка "Избранное" в списке статей
Описание: Отсутствует contentDescription
Рекомендация: Добавить android:contentDescription="@string/add_to_favorites"
```

**Исправление в коде:**

```kotlin
// Было
ImageButton(
    onClick = { toggleFavorite() },
    imageVector = Icons.Filled.Favorite
)

// Стало
ImageButton(
    onClick = { toggleFavorite() },
    imageVector = Icons.Filled.Favorite,
    modifier = Modifier.semantics {
        contentDescription = "Добавить в избранное"
    }
)
```

### 6. Безопасность данных (Data Safety)

#### Что проверяется

**Шифрование данных:**
- Передаются ли данные по HTTPS
- Хранятся ли чувствительные данные в зашифрованном виде

**Разрешения:**
- Соответствуют ли запрошенные разрешения функциональности
- Запрошены ли разрешения в нужный момент

**Сторонние библиотеки:**
- Используются ли библиотеки с уязвимостями
- Передают ли библиотеки данные третьим лицам

#### Рекомендации

```
ℹ️ Информация
Приложение передаёт данные через незашифрованное соединение (HTTP)
Рекомендация: Использовать HTTPS для всех сетевых запросов
```

**Исправление:**
- Настроить SSL/TLS на сервере
- Обновить URL API с http:// на https://
- Добавить Network Security Config для принудительного HTTPS

## Интерпретация результатов

### Критические проблемы (❌)

**Требуют немедленного исправления:**

- Краши при запуске на любом устройстве
- ANR более чем на 5% устройств
- Нарушение политик Google Play
- Уязвимости безопасности

**Порядок действий:**
1. Скачать подробный отчёт (PDF)
2. Изучить каждый краш
3. Воспроизвести локально
4. Исправить код
5. Протестировать
6. Загрузить новый релиз
7. Проверить Pre-launch report снова

### Предупреждения (⚠️)

**Рекомендуется исправить:**

- Проблемы с layout на отдельных устройствах
- Медленная загрузка экранов
- Высокое потребление батареи
- Проблемы доступности

**Порядок действий:**
1. Приоритезировать по влиянию на пользователей
2. Исправить в следующем релизе
3. Мониторить метрики после исправления

### Информационные сообщения (ℹ️)

**Полезно знать:**

- Статистика по устройствам
- Рекомендации по оптимизации
- Информация о сторонних библиотеках

**Действия:**
- Рассмотреть рекомендации
- Планировать улучшения на будущее

## Автоматизация проверки (опционально)

### Firebase Test Lab

Альтернатива Pre-Launch Report — использование Firebase Test Lab для запуска тестов на реальных устройствах.

**Настройка:**

```bash
# Установка gcloud CLI
curl https://sdk.cloud.google.com | bash

# Авторизация
gcloud auth login

# Запуск тестов
gcloud firebase test android run \
  --type instrumentation \
  --app app/build/outputs/apk/debug/app-debug.apk \
  --test app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk \
  --device model=shamu,version=31,locale=en,orientation=portrait \
  --timeout 300s
```

## Возможные проблемы и решения

### Проблема: Отчёт не генерируется

**Возможные причины:**
- Релиз ещё обрабатывается
- Прошло менее 30 минут с момента загрузки
- Технические проблемы на стороне Google

**Решение:**
1. Подождать 1-2 часа
2. Проверить статус релиза
3. Если не появилось — загрузить релиз заново
4. Обратиться в поддержку Google Play

### Проблема: Краш не воспроизводится локально

**Возможные причины:**
- Специфичное устройство/версия Android
- Редкое состояние гонки
- Проблемы с памятью на конкретном устройстве

**Решение:**
1. Изучить stack trace детально
2. Создать эмулятор с аналогичными характеристиками
3. Добавить дополнительное логирование
4. Запустить через Firebase Test Lab
5. Использовать робото-тесты для воспроизведения

### Проблема: Слишком много предупреждений

**Решение:**
1. Приоритезировать по влиянию на пользователей
2. Исправить самые важные сначала
3. Остальные запланировать на будущие релизы
4. Документировать принятые решения
