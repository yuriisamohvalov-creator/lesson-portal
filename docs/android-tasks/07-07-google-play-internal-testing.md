# Этап 7.7: Загрузка в Google Play Internal Testing

## Цель этапа

Загрузить подписанную сборку приложения в Google Play Console для внутреннего тестирования.

## Предварительные требования

- [ ] Аккаунт разработчика Google Play зарегистрирован
- [ ] Регистрационный взнос $25 оплачен
- [ ] Release AAB собран и подписан
- [ ] CI secrets настроены (Этап 7.6)

---

## Шаг 1: Регистрация аккаунта разработчика

### Создание аккаунта

1. Перейти на https://play.google.com/console
2. Войти через Google аккаунт
3. Нажать **Продолжить** (Continue)

### Тип аккаунта

**Выбрать тип аккаунта:**

| Тип | Для кого | Требования |
|-----|----------|------------|
| **Физическое лицо** | Инди-разработчики, фрилансеры | Паспортные данные |
| **Организация** | Компании, ИП | Регистрационные документы |

**Для Lessons Portal:** Выбрать соответствующий тип

### Оплата регистрационного взноса

1. Ввести данные банковской карты
2. Оплатить единовременный взнос **$25 USD**
3. Дождаться подтверждения оплаты (обычно мгновенно)

### Принятие соглашения

1. Прочитать **Соглашение разработчика распространения**
2. Принять условия
3. Аккаунт активирован

---

## Шаг 2: Создание приложения

### Начало создания

1. В Google Play Console нажать кнопку **Создать приложение** (Create app)
2. Заполнить форму

### Основная информация

| Поле | Значение |
|------|----------|
| **Название приложения** | Lessons Portal |
| **Язык по умолчанию** | Русский (Russian) |
| **Приложение или игра** | Приложение |
| **Бесплатное или платное** | Бесплатное |

Нажать **Создать приложение** (Create app)

### Подтверждение

Появится сообщение:
```
Приложение создано
ru.samoh.lessonsportal
```

Нажать **Начать работу с приложением** (Get started)

---

## Шаг 3: Настройка доступа к приложению

### Доступ к приложению (App Access)

Если приложение требует входа:

1. Перейти: **Доступ к приложению** → **Управление**
2. Выбрать: **Да, мое приложение требует входа**
3. Добавить тестовые учётные данные:
   - Email: `test@example.com`
   - Пароль: `TestPass123!`
4. Добавить инструкции для ревьюеров (опционально)
5. Сохранить

### Реклама в приложении

1. Перейти: **Реклама в приложении** → **Управлять**
2. Выбрать: **Нет, в моем приложении нет рекламы** (или Да, если есть)
3. Сохранить

### Content Rating (Возрастной рейтинг)

1. Перейти: **Рейтинг контента** → **Управлять**
2. Создать новый опросник (Create new questionnaire)
3. Ответить на вопросы:
   - Обычно для образовательного приложения: **3+** или **Для всех возрастов**
4. Получить рейтинг
5. Применить к приложению

## Шаг 4: Настройка Internal Testing

### Переход к внутреннему тестированию

1. В левом меню выбрать **Тестирование** → **Внутреннее тестирование** (Internal testing)
2. Нажать **Создать релиз** (Create new release)

**Примечание:** Если это первый релиз, может потребоваться завершить настройку приложения.

### Загрузка AAB

#### Способ 1: Через веб-интерфейс

1. На странице релиза найти секцию **Артефакты библиотеки Android App**
2. Перетащить файл `app-release.aab` или нажать **Выбрать файл**
3. Дождаться загрузки и проверки файла

**Путь к файлу:**
```
android/app/build/outputs/bundle/release/app-release.aab
```

#### Способ 2: Через API (опционально)

Использовать Google Play Developer API для автоматической загрузки.

### Проверка загруженного файла

После загрузки система проверит:

- ✅ Подпись приложения
- ✅ Version code (должен быть уникальным)
- ✅ Package name (должен совпадать)
- ✅ Минимальная версия Android
- ✅ Разрешения приложения

### Примечания к релизу

Добавить информацию о релизе:

```
Версия 1.0.0

Новые функции:
• Авторизация и управление сессией
• Каталог статей с pull-to-refresh
• Создание и редактирование статей
• Курсы и профили пользователей
• Комментарии к статьям
• Офлайн-режим с кэшированием
• Светлая и тёмная темы Material3
• Обработка ошибок API

Известные проблемы:
• Нет

Требования:
• Android 8.0+ (API 26)
```

Нажать **Далее** (Next)

## Шаг 5: Добавление тестировщиков

### Переход к вкладке тестировщиков

1. После создания релиза перейти на вкладку **Тестировщики** (Testers)
2. Нажать **Добавить тестировщиков** (Add testers)

### Создание списка рассылки

#### Вариант A: Google Group (рекомендуется)

1. Создать Google Group: https://groups.google.com
2. Название: `Lessons Portal Testers`
3. Email группы: `lessons-portal-testers@googlegroups.com`
4. Тип доступа: **Ограниченный** (только приглашённые)
5. Добавить email тестировщиков в группу
6. В Google Play Console ввести email группы

#### Вариант B: Email вручную

1. Ввести email-адреса тестировщиков через запятую:
   ```
   tester1@example.com, tester2@example.com, admin@example.com
   ```
2. Максимум 100 email для Internal Testing

### Сохранение списка

1. Дать имя списку: `Internal Testers`
2. Нажать **Сохранить изменения** (Save changes)

## Шаг 6: Публикация релиза

### Проверка перед публикацией

Перед отправкой проверить:

- [ ] AAB загружен успешно
- [ ] Version code корректный
- [ ] Примечания к релизу заполнены
- [ ] Тестировщики добавлены
- [ ] Доступ к приложению настроен
- [ ] Рейтинг контента получен

### Отправка на проверку

1. Нажать **Отправить на проверку** (Submit for review)
2. Подтвердить действие

**Для Internal Testing:**
- Проверка обычно не требуется
- Релиз становится доступен почти сразу (в течение нескольких минут)

### Статус релиза

После отправки статус изменится:
```
Статус: На рассмотрении → Доступно
```

## Возможные проблемы и решения

### Проблема: AAB не загружается

**Ошибка:**
```
Upload failed: You need to use the same signing key as previous releases
```

**Решение:**
- Использовать тот же keystore, что и для предыдущих релизов
- Если это первое приложение, проверить package name

**Ошибка:**
```
Upload failed: Version code already exists
```

**Решение:**
- Увеличить versionCode в `build.gradle.kts`:
  ```kotlin
  android {
      defaultConfig {
          versionCode = 2  // Было 1
          versionName = "1.0.1"
      }
  }
  ```
- Пересобрать AAB

### Проблема: Тестировщики не могут установить приложение

**Возможные причины:**
- Тестировщик не добавлен в список
- Ссылка неактивна
- Региональные ограничения

**Решение:**
1. Проверить, что email тестировщика есть в списке
2. Попросить тестировщика:
   - Перейти по ссылке точно
   - Нажать "Присоединиться" перед установкой
   - Использовать тот же Google аккаунт
3. Проверить региональную доступность

### Проблема: Релиз долго не публикуется

**Обычное время:** Несколько минут для Internal Testing

**Если дольше 1 часа:**
1. Проверить статус в Console
2. Проверить email на уведомления от Google
3. При необходимости обратиться в поддержку

### Проблема: Package name уже занят

**Ошибка:**
```
Package name 'ru.samoh.lessonsportal' is already in use
```

**Решение:**
- Использовать уникальный package name
- Изменить в `build.gradle.kts`:
  ```kotlin
  android {
      defaultConfig {
          applicationId = "ru.samoh.lessonsportal.unique"
      }
  }
  ```
- Пересобрать приложение

## Автоматизация через Fastlane (опционально)

### Установка Fastlane

```bash
sudo gem install fastlane --no-document
```

### Инициализация

```bash
cd android
fastlane init
```

### Настройка Supply

```bash
fastlane supply init \
  --package_name ru.samoh.lessonsportal \
  --json_key /path/to/google-play-api-key.json
```

### Загрузка релиза

```bash
fastlane supply \
  --aab app/build/outputs/bundle/release/app-release.aab \
  --track internal \
  --skip_upload_apk false
```

### Преимущества Fastlane

- Автоматизация загрузки
- Управление метаданными
- Скриншоты и описания
- Changelog management
